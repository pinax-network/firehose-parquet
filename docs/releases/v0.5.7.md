# firehose-parquet v0.5.7

`v0.5.7` is a quality-of-life release that adds compression metadata to streamed Parquet files, cleans up legacy metadata keys, fixes CLI table alignment, and introduces an `--overwrite` flag for partition index rebuilds.

## What's Changed

### 1. Compression metadata on streamed Parquet files

Streamed `*.parquet` files now carry the `firehose-parquet.compression` footer metadata key — the same metadata that `partitions.parquet` already included. This makes it possible to inspect any output file and know which codec was used without guessing.

**Before:** Only `partitions.parquet` had the compression metadata key.
**After:** All streamed Parquet files include `firehose-parquet.compression` in their footer metadata.

```bash
# Inspect metadata on any streamed parquet file
fireparq scan s3://bucket/eth/blocks/000100000-000100100.parquet --format metadata
```

> Closes #295 via PR #296

### 2. Removed legacy `partition_type` metadata

The legacy top-level `partition_type` metadata key has been removed from partition index files. The canonical key `firehose-parquet.partition` is now the sole partition metadata field, eliminating the duplication.

**Before:** Both `partition_type` and `firehose-parquet.partition` were written.
**After:** Only `firehose-parquet.partition` is written.

> Closes #297 via PR #298

### 3. Fixed `scan` table border alignment

`fireparq scan` in block format rendered table borders misaligned with numbered row entries. The header, separator, and border lines now share the same left boundary regardless of row-number width.

**Before:**
```
┌──────────┬──────────┐
│ block    │ tx_count │
├──────────┼──────────┤
 1. │ 100000   │ 142      │
 2. │ 100001   │ 89       │
```

**After:**
```
   ┌──────────┬──────────┐
   │ block    │ tx_count │
   ├──────────┼──────────┤
1. │ 100000   │ 142      │
2. │ 100001   │ 89       │
```

> Closes #299 via PR #300

### 4. `partitions build --overwrite` flag

`fireparq partitions build` now accepts `--overwrite` to rebuild the canonical partition index from scratch, ignoring any existing `partitions.parquet`. Previously the only way to regenerate the index was to delete the file manually.

`--overwrite` and `--resume` are mutually exclusive — the CLI will error if both are provided.

```bash
# Rebuild the partition index from scratch
fireparq partitions build s3://bucket/eth/blocks/ --overwrite

# Resume an interrupted build (unchanged)
fireparq partitions build s3://bucket/eth/blocks/ --resume
```

> PR #302
