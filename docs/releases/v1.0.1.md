# firehose-parquet v1.0.1

`v1.0.1` is a patch release of [v1.0.0](v1.0.0.md). It fixes S3 ownership on
Ceph RGW 19.2.x, where `build` and `recovery` could not start. It changes
no output format, schema, CLI flag or dataset state. A v1.0.0 dataset resumes
as it is, and no rebuild is needed.

## Fixes

### S3 ownership on Ceph RGW 19.2.x (#678)

On Ceph RGW 19.2.3 (Squid), v1.0.0 `build` failed at startup:

```
Error: acquiring all dataset ownership scopes
Caused by: conditional-write capability could not be proven; ownership was not acquired
```

RGW 19.2 compares an `If-Match` value literally with its stored ETag
*without* the quotes. It refuses the correct ETag in the quoted form that S3
returns and that AWS S3 and MinIO expect, and accepts it only unquoted.
Create-if-absent (`If-None-Match: *`) works, so Delta log commits weren't
affected. fireparq's own compare-and-swaps were: the owner record, the
`.fireparq-ingest/` authority and pending records, the S3 cursor mirror, and
the pinned read that verifies each uploaded part.

The conditional-write canary now chooses the ETag form for each store:

- It runs as before with ETags as returned. AWS S3, MinIO and other RFC 9110
  providers pass here, and nothing changes for them.
- If exactly the correct version is refused with a precondition failure
  (on the conditional GET or the correct compare-and-swap), the whole canary
  runs again on a fresh probe key with unquoted ETags. That form is adopted
  only if every step passes, including the refusal of wrong and stale
  versions. The choice is logged once:
  `s3 conditional writes: If-Match ETags sent unquoted (provider compares them literally)`.
- If neither form passes, it fails closed with the same error as before.

Every conditional request through the owner then uses the chosen form, for
the whole run. Forms are never mixed or retried per request. The choice isn't
persisted, so each start qualifies the provider again. A missing or unusable
ETag still fails closed, and probe keys are handled as before. The canary
also gained one step: a GET pinned to the correct version must serve it.

To check a provider before deploying, an opt-in test runs only the canary
against a disposable bucket and prefix and prints the chosen form. CI never
runs it. See the [record](../audit/rgw-if-match-etag.md).
