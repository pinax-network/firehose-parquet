# firehose-parquet v1.1.1

`v1.1.1` is a patch release of [v1.1.0](v1.1.0.md). It fixes v1.1.0's
`build`, which could not read the control records that the v1.0.2–v1.0.7
Docker images wrote. It changes no output format, schema, CLI flag or dataset
state. A v1.0.x or v1.1.0 dataset resumes as it is, and no rebuild is needed.

## Upgrade

Upgrade from v1.0.x to v1.1.1, not to v1.1.0. The
[v1.1.0 upgrade notes](v1.1.0.md#upgrade) apply: the maintenance CronJobs run
the writer's image with `args: ["maintenance"]`.

## Fixes

### v1.1.0 writers could not read their control records (#698, #699)

On riv-dev1, every v1.1.0 writer stopped at startup with:

```
Error: control record checksum mismatch
```

The writers were rolled back to v1.0.4 and resumed. v1.1.0 failed while
reading the records, so it rewrote none of them.

`.fireparq-ingest/state.json` and `pending.json` carry a SHA-256 of their
payload. A reader checked it by parsing the payload and serializing it again,
which only gives back the writer's bytes if both order JSON object keys the
same way. That order is a build-time choice, serde_json's `preserve_order`
feature:

- The v1.0.2–v1.0.7 Docker images had it, through the maintenance crate's
  DataFusion and a build without `-p`, so they wrote keys in field order.
- v1.1.0, every release tarball, and v1.0.0/v1.0.1 don't, so they sort keys.

So v1.1.0 rejected every record an image had written. The checksum is now
checked over the payload exactly as stored. Any version reads any version's
records, including a rollback to an earlier image, and what a writer stores is
unchanged.

The Docker image now builds `fireparq` with `--locked -p blocks`, the same
features as the release tarball. See the
[record](../audit/698-control-record-key-order.md).
