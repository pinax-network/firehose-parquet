# firehose-parquet v1.6.0

`v1.6.0` is a minor release of [v1.5.0](v1.5.0.md). `fireparq maintenance`
takes `OPTIMIZE=0`, for checkpoint-only runs beside a compaction run that
takes hours (#728). Nothing else changes: the writer, every schema and every
digest are those of v1.5.0, so datasets resume as they are and no rebuild is
needed.

## Upgrade

- **Writers and maintenance jobs:** move to the new image tag
  (`ghcr.io/pinax-network/firehose-parquet:1.6.0`). Existing schedules behave
  as before: `OPTIMIZE` defaults to `1`. Files written after the upgrade carry
  `firehose-parquet.version` `1.6.0`; maintenance leaves the key out of a
  compacted day that spans the upgrade.
- **Beside a parallel backfill:** add a frequent run with `OPTIMIZE=0` and
  `VACUUM=0` next to the compaction run
  ([Checkpoint-only runs](../delta-maintenance.md#checkpoint-only-runs)). Only
  that run needs the new image: lanes on v1.5.0 keep running.
- **Rollback:** v1.5.0 runs on the same datasets. It reads `OPTIMIZE=0` as
  nothing and compacts, so remove the checkpoint-only schedule first.

## Known issues

- **A checkpoint-only run has not run on production storage yet.** Its tests
  use local tables. Time one run on the largest table before choosing the
  interval: a checkpoint loads the table's whole state, and the log cleanup
  lists its whole `_delta_log/`.

## New features

- **Checkpoint-only maintenance: `OPTIMIZE=0` (#728, #732).** A writer's
  commit time grows with a table's commits since its last checkpoint. A run
  only checkpoints a table after compacting it, and beside a parallel backfill
  a run takes hours, so tables went thousands of commits without a checkpoint:
  on a 15-lane backfill a commit to `logs` took 49 s at 4,535 commits behind,
  against 3 s for a table 49 behind. `OPTIMIZE=0` skips compaction and the
  read of `blocks` for the open date; with `VACUUM=0` a run only writes a
  checkpoint and cleans up the log. It commits nothing, so it conflicts with
  neither the writers nor the compaction run. The `start` line gains
  `optimize`. See
  [Checkpoint-only runs](../delta-maintenance.md#checkpoint-only-runs).
