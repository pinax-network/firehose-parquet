# firehose-parquet v1.6.0

`v1.6.0` is a minor release of [v1.5.1](v1.5.1.md). New EVM datasets no longer
have the gas-change tables, which block version 5 of the EVM Firehose tracer
no longer fills. The maintenance job can compact several days of a table at
once. Two dependency advisories are fixed. Output formats and schemas are
unchanged. **An existing EVM dataset with extended output must set
`WITH_GAS_CHANGES=true` before it upgrades**: without it, `build` refuses to
resume it.

## Upgrade

- **Existing EVM datasets with extended output** (writers and backfill lanes,
  created by v1.5.1 or earlier): set `--with-gas-changes`
  (`WITH_GAS_CHANGES=true`) first, then move to the new image tag
  (`ghcr.io/pinax-network/firehose-parquet:1.6.0`). They then resume as they
  are, with the same tables, schemas and digests. v1.5.1 ignores the
  variable, so it can be set before the upgrade. Without it, `build` refuses
  to start and names the flag, before any Blocks request
  ([Gas-change tables](../chains/evm.md#gas-change-tables)).
- **New EVM datasets:** 18 tables with extended output, without
  `gas_changes` and `system_gas_changes`. Leave the flag unset unless they
  are wanted.
- **Other chains, and EVM without extended output:** nothing to do. The flag
  has no effect there, and `build` logs a warning if it is set.
- **Maintenance jobs:** move to the new image tag. `OPTIMIZE_CONCURRENT_DATES`
  defaults to `1`, which behaves as before; the only new output is the `date`
  line for each committed day.
- **Rollback:** v1.5.1 runs on the same datasets. It ignores
  `WITH_GAS_CHANGES` and `OPTIMIZE_CONCURRENT_DATES`, and always declares the
  gas-change tables, so it refuses an EVM dataset created by v1.6.0 without
  them.

## Breaking changes

- **New EVM datasets no longer have `gas_changes` and `system_gas_changes`
  (#738).** Block version 5 of the EVM Firehose tracer records no gas changes.
  `--with-gas-changes` (`WITH_GAS_CHANGES=true`) writes them as before, with
  the same schemas and digests. Set it on every existing EVM dataset with
  extended output (writers and backfill lanes) before upgrading; without it
  `build` refuses to start, naming the flag
  ([Gas-change tables](../chains/evm.md#gas-change-tables)).

## New features

- **`fireparq maintenance` compacts several days of a table at once:
  `OPTIMIZE_CONCURRENT_DATES` (#737, #740).** Each day is its own commit, and
  each is handed out once within the run; never split a table's backlog over
  several jobs instead (#717). Each day is reported as soon as it commits or
  fails (new `date` and `date_error` lines); the `table` line is unchanged.
  Memory and CPU grow with the setting, and the default, `1`, keeps the
  previous behaviour
  ([Several days at once](../delta-maintenance.md#several-days-at-once)).

## Fixes

- **Dependency updates for two advisories, and one advisory ignored (#739).**
  Only `Cargo.lock` and `deny.toml` changed:
  - parquet 60.2.0 and 59.3.3, with the rest of arrow at the same versions
    (RUSTSEC-2026-0595: Bloom filters written in plaintext when writing
    encrypted Parquet; fireparq writes no encrypted Parquet).
  - url 2.5.9 (RUSTSEC-2026-0592: stack overflow in `Url::origin()` on nested
    `blob:` URLs).
  - RUSTSEC-2026-0543 (chrono is unmaintained) is ignored: there is no
    patched release, and arrow and delta-rs depend on chrono too.
