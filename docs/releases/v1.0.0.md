# firehose-parquet v1.0.0

`v1.0.0` is the first major release of `firehose-parquet`. It is the result of a
full code audit of the project (tracking issue #463): 88 pull requests merged
since `v0.7.2` that fix data loss and crash-safety bugs, make the output schema
consistent and complete across chains, and harden every command that writes to
local disk or S3.

Almost every audit fix changes an output schema, a CLI default, or the state
that `fireparq` keeps next to a dataset. **This is a breaking release: existing
datasets must be rebuilt into a new output root.** Read the
[upgrade guide](#upgrade-guide-read-first) before deploying.

## Summary

- **Data-integrity hardening.** `build` now writes every flush as one all-table
  transaction with deterministic part names, output authority under
  `.fireparq-ingest/` and recovery before any new block is requested, so a crash,
  a failed write or a replay can no longer lose or duplicate rows. `merge` and
  `rollup` are journaled and crash-safe, and every mutating command takes
  dataset ownership.
- **One consistent schema across chains.** The canonical `timestamp` is
  `Timestamp(Millisecond, UTC)` everywhere, day directories are `day=DD`, column
  names are unique, and every chain gains columns and tables that were dropped
  before (EVM withdrawals, access lists and EIP-7702 authorizations, Beacon
  execution requests, NEAR receipt actions and logs, Tron contracts, and more).
- **Failed transactions are modeled explicitly.** EVM includes failed
  transactions by default with only their persistent state changes; Solana,
  Tron, Antelope and NEAR rows carry their transaction or receipt outcome.
- **Verifiability v2.** `verify` computes versioned `merkle_v2` roots that detect
  duplicated rows and cover every Arrow type, keeps one registry per network,
  never writes a registry from a failing run, and can run beside `build`.
- **Provider-scoped credentials and explicit S3 destinations.** Firehose
  credentials are only sent to the provider they belong to, `.env` is read from
  the working directory only, and every S3 write needs an explicit
  `s3://bucket/prefix`.
- **Exact partition indexes.** `partitions.parquet` v2 records verified finalized
  coverage, and consumers refuse incomplete or ambiguous matches.
- **Engine-friendly dataset root.** The cursor mirror, partition index, Merkle
  registry and verify reports live in `<dataset root>/_fireparq/`, so the root
  holds only table directories, `_fireparq/` and dot-prefixed control state,
  which Spark, Trino, Hive and Delta skip (#647, PR #650).
- **Performance.** Faster encoding on every chain, adaptive compressed file
  sizes, tuned gRPC receive windows, bounded-memory `verify` and `rollup`,
  disk-spooled S3 uploads and concurrent S3 maintenance.

## Upgrade guide (read first)

### 1. Rebuild into a new output root

Do not point `v1.0.0` at a dataset written by `v0.7.x`. Build into a new, empty
output root (for example `s3://my-bucket/v1` next to your existing
`s3://my-bucket/v0`) and keep the old root read-only until the rebuild has
caught up.

Why a rebuild is required:

- **Schemas changed on every chain.** Columns were added, renamed and retyped,
  and tables were added (see [Schema changes by chain](#schema-changes-by-chain)).
  `merge` and `rollup` refuse to combine files with different schemas (#479), so
  old and new files cannot be compacted together.
- **The canonical `timestamp` type changed** from `Timestamp(Second, UTC)`
  (written as a plain Parquet `INT64`) to `Timestamp(Millisecond, UTC)` (a real
  Parquet `TIMESTAMP`), on every table (#491).
- **Partition keys changed.** Day directories are `day=DD` instead of `date=DD`
  (#493).
- **Row selection changed.** EVM now includes failed transactions, Solana vote
  filtering keeps administrative activity, Tron excludes failed smart-contract
  calls, Antelope keeps `onerror` handlers and scheduled transactions, and
  several index columns were renumbered.
- **Protected ingestion state is new.** `build` only resumes from the output
  authority it keeps under `<output>/<chain_name>/.fireparq-ingest/`. That
  authority binds the chain, mapper version, table schema digests, encoding,
  effective feature flags, partitioning and storage of the dataset. Outputs
  written by `v0.7.x` have no authority, and `build` refuses to adopt them or
  their `cursor.parquet` (#468). A new root must be empty and must not contain a
  cursor mirror.
- **Derived artifacts changed format.** `verify` registries hold `merkle_v2`
  roots at a new location (#487, #488), and `partitions.parquet` is v2 with
  millisecond time columns (#486).

Querying old and new data side by side: keep the two roots separate and
normalize the old files in the query. In DuckDB:

```sql
-- v0.7.x files: timestamp is BIGINT seconds and the day directory is date=DD.
-- Disable hive partitioning for the old tree so `date` stays the DATE column.
SELECT * REPLACE (to_timestamp("timestamp") AS "timestamp")
FROM read_parquet('s3://my-bucket/v0/mainnet/blocks/**/*.parquet', hive_partitioning = false)
WHERE block_num < 21000000
UNION ALL BY NAME
SELECT * EXCLUDE (year, month, day)
FROM read_parquet('s3://my-bucket/v1/mainnet/blocks/**/*.parquet', hive_partitioning = true)
WHERE block_num >= 21000000;
```

The example assumes day-partitioned output; adjust the excluded partition
columns to your layout. `UNION ALL BY NAME` fills columns that only exist in the
new files with `NULL` for old rows. Only do this for tables whose existing
columns kept their type and meaning; check the per-chain tables below, and
prefer rebuilding a range over reconciling it in SQL. Some columns keep their
Arrow type but change their values, so a union will not flag them: Beacon
`execution_payload.base_fee_per_gas` (hex bytes before, a decimal string now),
NEAR `state_changes.block_id` / `parent_id` (hex before, base58 now), Solana
`rewards.reward_index` and every table where row selection changed. Select
columns by name, never by position. `verify` roots of old and new files differ;
rebuild each registry against the new root.

### 3. Deployment notes

- **Explicit S3 output (Kubernetes).** Replace `S3_BUCKET` plus a relative
  `OUTPUT` with an explicit URI. Kubernetes expands `$(VAR)` references to
  variables defined earlier in the same container:

  ```yaml
  env:
    - name: BUCKET_NAME
      valueFrom:
        configMapKeyRef: { name: fireparq, key: bucket }
    - name: OUTPUT
      value: s3://$(BUCKET_NAME)/v1
  ```

  Deployments that are not migrated exit with an error before writing. Keep
  `S3_BUCKET` only as a consistency check (it must match the `OUTPUT` bucket) or
  for read-only shorthand keys. Check the `resolved write destinations` log line
  after rollout.
- **One bucket per network (Kubernetes).** `build` appends the endpoint's
  `chain_name` to `OUTPUT`, so `OUTPUT=s3://ethereum-mainnet` writes
  `s3://ethereum-mainnet/mainnet/...`. Set `WITHOUT_CHAIN_DIR=true`
  (`--without-chain-dir`) to write the dataset at the bucket root instead:
  `s3://ethereum-mainnet/<table>/year=YYYY/month=MM/day=DD/part-*.parquet`, with
  `.fireparq-ingest/` and `_fireparq/` (cursor mirror, index, registry) beside
  the tables. Set it on
  `partitions build` too, and point `verify` at `s3://<bucket>/<table>`.

  ```yaml
  env:
    - name: BUCKET_NAME
      valueFrom:
        configMapKeyRef: { name: fireparq, key: bucket }
    - name: OUTPUT
      value: s3://$(BUCKET_NAME)
    - name: WITHOUT_CHAIN_DIR
      value: "true"
  ```

  Choose it before the first run: the root is part of the protected dataset
  identity, and a later run with the other setting overlaps the existing
  dataset and is refused before any Blocks request. The bucket must be empty
  for the first `build` (the owner record and a same-chain
  `_fireparq/partitions.parquet` may exist). Bucket-wide ownership (below) already means one writer per
  bucket, so one bucket per network also gives every network's `build` its own
  owner.
- **S3 ingestion needs explicit keys and an HTTPS endpoint.** Every S3 `build`
  (output or cursor) needs both `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`;
  the provider credential chain alone is not enough. A custom
  `--aws-endpoint-url` / `AWS_ENDPOINT_URL_S3` must be `https://` with a host
  (#520, PR #613). The check runs after EndpointInfo and before any S3 request;
  `--dry-run` skips it.
- **Writable temporary directory for the S3 upload spool.** S3 ingestion writes
  its upload spool to the system temporary directory (`$TMPDIR`, else `/tmp`);
  there is no separate flag. Each part is encoded to an anonymous spool file and
  verified through a second spool of the same size before it is committed, so
  plan for roughly two encoded parts of free space for every part in flight. With
  the default flush concurrency (#516) several parts can be in flight: encoded
  parts are bounded by `--flush-inflight-bytes` (256 MiB) and up to
  `--flush-publish-concurrency` (4) readback spools exist at once, so allow
  about 256 MiB plus 4 × the largest part (about 400 MiB with the 32 MiB
  default), more when a table outgrows the target. `--flush-inflight-bytes 1`
  brings it back to about two encoded parts. Kubernetes pods with
  `readOnlyRootFilesystem: true` need a writable volume there, for example an
  `emptyDir` mounted at `/tmp`.
- **S3 bucket requirements.** Mutating commands hold a persistent owner record,
  `.fireparq-owner-v1.json` at the bucket root. The bucket must support
  conditional writes (`If-Match` / `If-None-Match`) and object versions, and the
  credentials need read/write on `.fireparq-owner-v1.json` and
  read/write/delete below `.fireparq-owner-probes-v1/`.
- **One writer per output root, and on S3 one writer per bucket.** Each dataset
  has exactly one owner at a time: a second `build`, `partitions build`, `merge`,
  `rollup` or `truncate` on the same root, or on an ancestor or descendant
  directory, fails immediately instead of racing. On S3 the owner covers the
  whole bucket: a second mutating command on **any** prefix of the same bucket
  fails with `bucket ownership is held; there is no age-based or automatic
  takeover`. Give each concurrently running S3 writer (for example one `build`
  per network) its own bucket, and run compaction (`merge`, `rollup`) or
  `truncate` only when no `build` is writing to that bucket (#636). `verify`
  does not take ownership and can run beside `build`.
- **When an S3 owner is kept after a failure (#640).**
  - `build` releases the bucket owner on exit, as a successful run does, when
    every request it sent had a definite outcome: failures before any mutation,
    failures after resolved mutations (including a failed transaction left
    pending, which the next `build` recovers before streaming), and HTTP
    401/403 refusals, which the provider did not apply. A first SIGINT/SIGTERM
    also releases it.
  - `build` keeps the owner after an ambiguous request (timeout, lost
    acknowledgement, connection reset, unverifiable readback, 5xx, 409/412),
    after a second signal (exit 130), after a panic, or when the release request
    itself fails. Its error then names the owner UUID and generation, why it was
    kept, and the exact `recovery status` and `recovery release` commands.
  - `merge`, `rollup`, `truncate`, `partitions build` and `recovery` still keep
    the owner after **any** error, and log the same guidance.
  - A kept owner makes every later writing command on the bucket fail until it
    is released: run `fireparq recovery status s3://bucket/prefix`, confirm that
    the old process is gone and that the provider has finished its requests,
    then run `fireparq recovery release` with `--expected-owner`,
    `--expected-generation`, `--stopped-writer-evidence` and
    `--provider-quiescence-evidence`. Process exit or elapsed time alone is not
    proof. Local outputs release their directory locks when the process exits.
- **Recovery.** A crash leaves a journal that the next `build` (or maintenance
  command) recovers before doing anything else. `fireparq recovery recover
  <path>` runs the same recovery offline for protected ingestion, the cursor
  mirror and merge journals (an interrupted `rollup` is finished by re-running
  the same `rollup`). `recovery` commands read `AWS_ENDPOINT_URL_S3` like every
  other command; `AWS_ENDPOINT_URL` is used only when neither
  `--aws-endpoint-url` nor `AWS_ENDPOINT_URL_S3` is set (#639).
- **Local filesystems** must support atomic hard links and file and directory
  `fsync`, and directory ancestors must be readable (#578). Local ownership uses
  directory inode locks on macOS and Linux.
- **Temporary `.fireparq-txn-*.tmp` files** belong to a transaction in progress.
  Do not delete them by hand; the next `build` or `recovery recover` cleans them
  up.

## Highlights by area

### Ingestion safety

`v0.7.x` wrote each table on its own and saved `cursor.parquet` afterwards. A
failed table write could drop that table's buffer and still save the cursor
past the lost rows (#464), an unreadable cursor silently restarted ingestion
from genesis (#465), random part names duplicated data on replay (#468), and a
cursor save failure only logged a warning (#469).

In `v1.0.0`, every flush is one all-table transaction (#468):

1. the complete flush is validated, journaled and assigned deterministic
   `part-v1-*` names;
2. each part is staged, published and verified (locally with `fsync` and atomic
   publication, #578; on S3 with one conditional PUT and a readback, #520);
3. the output authority under `.fireparq-ingest/` advances, then the optional
   `_fireparq/cursor.parquet` mirror.

A crash at any point is recovered before the next Blocks request: parts of an
uncommitted transaction are removed, a committed one is rolled forward, and the
replayed window republishes identical names. On mainnet test data, an
interrupted write recovered to exactly the rows of an uninterrupted run across
14 tables. Other ingestion fixes: blocks below `--start-block` are no longer
written (#466), bounded runs must prove their stop block (#466), EndpointInfo
failures stop start-up instead of changing the output path (#467), fatal gRPC
errors stop instead of retrying forever (#472), shutdown is prompt (#473) and
invalid timestamps are errors (#476).

### S3

- Every S3 write needs an explicit `s3://bucket/prefix`, and `.env` is never read
  from a parent directory (#617). A run in a checkout below a production `.env`
  once wrote to a production bucket during the audit.
- Mutating commands hold a persistent, conditional bucket-wide owner, and remote
  data mutations make exactly one attempt; an uncertain result keeps ownership
  for explicit recovery instead of being retried blindly (#468).
- Ingestion uploads spool each encoded part to disk and stream one conditional
  PUT with explicit deadlines, instead of buffering it in memory behind a
  30-second request timeout (#520).
- An explicit `s3://` cursor uses its own bucket (#470).
- Maintenance deletes run up to ten at a time and `merge` reads bounded windows
  of pinned objects (#523); `rollup` reads S3 sources through pinned byte ranges
  (#522).

### Verify

`merkle_v2` fixes three ways the old roots could hide changes: a duplicated
trailing row had the same root (#487), roots depended on Arrow display
formatting (#490), and every UTC timestamp was hashed as the same constant. The
registry moves to one file per network at
`<output>/<chain_name>/_fireparq/merkle_roots.parquet` (#488, #647), a failing or partial run never writes it, and concurrent writers cannot
lose rows (#489). `verify` no longer needs to avoid `build`: it reads without
ownership, reports partitions the writer can still extend as `open`, and fails
cleanly if a file changes underneath it. Memory stays flat with row count (#521).

### Partitions

`partitions.parquet` v2 (#486) records which finalized blocks were actually
checked, keeps backward timestamp runs instead of assuming monotonic time, and
no longer publishes current-head or incomplete live spans as complete.
`partitions resolve` refuses incomplete or ambiguous matches by default. Also
fixed: `block_range` rows sorted as strings (#482), bounded builds that
destroyed or duplicated an existing index (#483), and probe timeouts treated as
missing blocks (#485). Index time columns are real Parquet timestamps.

### Maintenance

`merge` and `rollup` are journaled and recover an interrupted run to exactly the
original rows, locally and on S3 (#478, #480). They no longer combine files with
different schemas or value metadata (#479), leave root artifacts alone, and
`rollup` re-runs no longer delete or duplicate their own output (#478; on
mainnet test data a second in-place run used to delete the whole dataset).
`truncate` needs `--yes` and ANDs filters across keys (#481). `rollup` streams
bounded batches instead of holding a target group in memory (#522).

### CLI

- `--env-file`, `--cursor none`, `--exclude-failed-transactions`,
  `--flush-memory-bytes`, the flush concurrency options, `--compression
  zstd:<level>`, gRPC receive options, `--metrics-stale-after-secs`,
  `--without-chain-dir`, `partitions resolve --all-spans`, `truncate --yes` and
  the `recovery` subcommands are new.
- Zero consistently means "disabled" for flush thresholds and timeouts, and
  values that crashed are rejected (#471).
- `--final-blocks-only=false` enables append-only non-final output (#474).
- The built-in network registry is regenerated and checked weekly (#535).
- Startup logs name the loaded env file, the resolved write destinations and the
  selected credential variables, never secret values.

### Metrics

Counter names have a single `_total` suffix, `files_written_total` no longer has
an unbounded `partition` label, and gauges that were misleading or always zero
are gone (#475). `/ready` reflects whether the stream is actually delivering
messages. New counters cover fatal gRPC errors, cursor save failures and blocks
skipped below the start block.

end-to-end live-ingestion claims.

### Security

- **Credential scoping (#562).** Firehose credentials are sent only to the
  provider they belong to; previously a Pinax key was sent to StreamingFast
  endpoints behind the moved aliases.
- **No writes through parent `.env` files (#617)**; see S3 above.
- **Dependency advisories.** Compatible dependency updates and the Arrow/Parquet
  60 upgrade resolve RUSTSEC-2026-0009, -0037, -0041, -0049, -0097, -0098,
  -0099, -0104, -0185, -0190, -0258 and -0285, and remove the vulnerable Thrift
  dependency (GHSA-2f9f-gq7v-9h6m) (#567, #568; PRs #569, #577, #615). Parquet
  60 also bounds allocations from malformed footer list lengths.
- **cargo-deny in CI.** A pinned, checksum-verified cargo-deny runs
  `cargo deny --locked check advisories` on every push and pull request, and on
  its own every Monday at 05:41 UTC (`.github/workflows/advisories.yml`, check
  name `Dependency advisories / cargo deny check advisories`). Every RustSec
  vulnerability fails the job; unsound and unmaintained advisories fail for
  direct dependencies. Ignored advisories need a recorded reason in `deny.toml`.

## Detailed changelog

Each entry links its issue and pull request(s). The implementation record of
each issue is in [`docs/audit/`](../audit/README.md).

### Breaking changes

#### Ingestion and dataset state

- **All-table ingestion transactions and output authority (#468; PRs #591,
  #600, #619).** `build` journals each complete mapper flush as one transaction
  across all tables and recovers it before opening the Blocks stream. Parts use
  deterministic `part-v1-<stream>-<first>-<last>-<transaction>-<index>.parquet`
  names, so a replayed window republishes the same names instead of adding
  duplicates, and parts of an interrupted transaction are rolled back before
  replay or verified and rolled forward after commit. Output authority under
  `<chain_root>/.fireparq-ingest/` selects the exact accepted cursor, including
  filtered zero-row events and timestamp-routing provenance;
  `_fireparq/cursor.parquet` is an optional mirror whose deletion cannot rewind
  output. The chain, mapper and
  schema digests, encoding, effective feature flags, partition policy, storage
  and mirror binding are immutable for a dataset. Flush thresholds and
  compression stay tunable. A new dataset needs an empty root and an absent
  mirror; existing random-name output and legacy cursors are refused rather
  than adopted. Unknown custom chain metadata needs an explicit `--block-type`
  before recovery. An ordinary error removes the failed transaction's hidden
  `.fireparq-txn-*.tmp` staging files and keeps its journal; after a kill, the
  next `build` or `recovery recover` removes them. Plain-glob readers still do
  not get atomic multi-table snapshots.
- **`--cursor-override` is refused by a real `build`, and `--cursor none` creates
  a dataset without a mirror (#468, PR #619).** `--cursor-override` cannot bypass
  protected state and is rejected even at a new root (it remains available to a
  read-only `--dry-run`). `--cursor none` (case-insensitive) keeps mandatory
  authority without a mirror; the choice is bound to the dataset, later runs
  must repeat it, and it cannot be combined with `--cursor-template`.
- **Ownership for every mutating command (#468 prerequisite, PR #591).** `build`,
  `partitions build`, `merge`, `rollup`, `truncate` and `recovery` coordinate
  ownership of their source, output and cursor locations. Local mutation needs
  supported macOS/Linux directory inode locking and readable ancestry; nested
  symlinks inside guarded trees are refused. S3 mutation holds a persistent
  bucket-wide owner and requires conditional create/update support, usable
  object versions and access to `.fireparq-owner-v1.json` and
  `.fireparq-owner-probes-v1/`. The owner covers the whole bucket: a second
  mutating command on any prefix of it fails immediately, and there is no
  expiry, automatic takeover or best-effort fallback for stores without
  conditional writes. Remote data writes, deletes and cursor saves make one
  attempt with transport retries disabled. A failed `build` releases the owner
  when every request it sent had a definite outcome (#640); after an ambiguous
  request, and after any error of the maintenance commands, the owner is kept
  until `fireparq recovery release` frees it after provider-confirmed quiescence
  (see Deployment notes).
- **Bounded runs must prove their stop block (#466, PRs #544, #600).** A run with
  `--stop-block` exits 0 only after block `stop_block - 1` was received and
  committed. A stream that ends early is resumed once from authority; if the
  server has no more blocks, the committed prefix is kept and the command exits
  non-zero on every chain, including chains with skipped slots or heights
  (Solana, NEAR, Beacon), because a sparse or empty tail cannot prove the bound.
  Choose a stop bound that ends at an observed block. `--dry-run` applies the
  same rule. An already proven bound makes no Blocks request.
- **Start-up requires EndpointInfo (#467, PR #570).** Ingestion stops before
  resolving output and cursor paths if endpoint metadata cannot be read. Info is
  tried up to three times with bounded back-off; authentication errors, an
  unsupported Info RPC and empty chain names fail promptly. Explicit network,
  block type or start bounds do not bypass this, so a transient failure can no
  longer change the output prefix or resume point.
- **Invalid timestamps and missing stream metadata are errors (#476, PR #584).**
  Malformed timestamp seconds or nanos, and values outside years -9999 to 9999,
  fail before any row or partition file is written instead of falling back to
  1970, saturating or panicking. Streamed blocks must carry a metadata object.
- **Local publication requires durable filesystem operations (#578, PR #580).**
  Local parts become visible at their final name only after the footer is
  complete and the file is synced; publication is atomic and never overwrites a
  destination. Filesystems must support atomic hard links and file/directory
  sync, and directory sync failures are fatal.
- **EVM includes failed transactions by default (#494, PR #547).** A failed EVM
  transaction still pays gas and fees and increments the sender's nonce. `build`
  now writes it with all of its calls and gas changes, and only the state changes
  that persist: root-call `balance_changes` with reason `GAS_BUY`, `GAS_REFUND`,
  `REWARD_TRANSACTION_FEE` or `INCREASE_MINT`; the sender's nonce increment plus
  one `nonce_changes` row per accepted EIP-7702 authorization; at most one
  `code_changes` row per accepted authorization; no storage changes, account
  creations or other balance changes. `--exclude-failed-transactions`
  (`EXCLUDE_FAILED_TRANSACTIONS`) restores the previous EVM output and wins over
  `--include-failed-transactions` on every chain that filters failed
  transactions;
  `--include-failed-transactions` is deprecated for EVM, has no effect there and
  logs a warning. A protected EVM output created with
  `--exclude-failed-transactions` keeps excluding failed transactions when
  resumed (with a warning unless the flag is repeated); switching needs a new
  root. EVM outputs built with `--include-failed-transactions` before this
  release contain rolled-back transfers and storage writes; rebuild them to
  reconcile state.
- **Tron excludes failed smart-contract calls, and Antelope keeps `onerror`
  handlers and scheduled transactions (#550, PR #622).** Tron's filter used the
  Firehose wrapper `result`, which java-tron sets to success for every included
  transaction, so reverted and out-of-energy calls were always written. A Tron
  transaction now fails when `TransactionInfo.result` is `FAILED` or its receipt
  result is neither `DEFAULT` nor `SUCCESS`, and failed transactions are excluded
  unless `--include-failed-transactions` is set. Antelope kept only `EXECUTED`
  traces; a trace now succeeds when it has no exception and its status is
  `EXECUTED`, `SOFTFAIL` or `DELAYED`, so `onerror` handlers and scheduled
  transactions are kept, while the failed deferred trace beside an `onerror`
  handler, `HARDFAIL` and `EXPIRED` stay excluded. NEAR receipt rows are always
  written and now carry `receipt_status`.
- **Solana vote filtering keeps administrative activity (#501, PR #586).** The
  vote table and `--without-votes` apply only to legacy single-instruction votes
  with fully decoded, recognized payloads. Withdraw, Authorize, vote-account
  creation, mixed instructions, unused Vote program keys, versioned transactions
  and unknown payloads keep their ordinary detail rows. Schemas are unchanged,
  but affected rows and verification roots change.
- **`--flush-bytes` is an adaptive compressed-file target (#515, PR #605).**
  `build --flush-bytes` targets the largest compressed file of a flush, using
  feedback from committed transactions, instead of the raw in-memory size of the
  largest table. `build`, `merge` and `rollup` share a 32 MiB default (`rollup`
  and the library `Config` used 128 MiB). `build` also flushes when the sum of
  mapper estimates reaches `--flush-memory-bytes` (default 256 MiB), which stays
  active with `--flush-bytes 0`; it is not an RSS cap and one block can overshoot.
- **Parquet layout and explicit Zstandard levels (#519, PR #608).** Ingestion and
  maintenance share bounded Bloom filters on lookup columns, a 65,536-row group
  maximum and, for complete ingestion parts, block-number sort metadata. Arrow
  schemas, values and row order are unchanged. `--compression zstd:<level>`
  selects a level; plain `zstd` stays level 3. Non-default levels are bound into
  pending transaction identities, so finish any recovery before downgrading.

#### Output layout and schemas

- **fireparq's artifacts live in `<dataset root>/_fireparq/` (#647, PR #650).** The
  default cursor mirror is `_fireparq/cursor.parquet` (`--cursor`, relative to
  the dataset root), `partitions build` writes `_fireparq/partitions.parquet`
  and reads `_fireparq/cursor.parquet` to infer `--start-block`, and `verify`
  keeps `_fireparq/merkle_roots.parquet` and `_fireparq/verify_runs/`. This
  holds below `<output>/<chain_name>` and at a `--without-chain-dir` root. The
  root then holds only table directories, `_fireparq/` and dot-prefixed control
  state (`.fireparq-ingest/`, `.fireparq-owner-v1.json`,
  `.fireparq-owner-probes-v1/`), which Spark, Trino, Hive, Athena and Delta skip;
  DuckDB users glob per table (`<root>/<table>/**/*.parquet`). Every walker
  (`merge`, `rollup`, `truncate`, `scan`, `validate`, `verify`, recovery and S3
  listings) reserves the whole `_fireparq/` subtree and the legacy root names;
  a `truncate` partition filter never matches them. Nothing is migrated: a
  legacy root `merkle_roots.parquet` makes a default-registry `roots` run fail,
  a legacy root `partitions.parquet` makes every `partitions build` mode and a
  new `build` fail, each naming the move into `_fireparq/`. The mirror location
  stays bound at creation: a dataset created with the old default refuses the
  new one and is resumed with `--cursor cursor.parquet`. Local writes create
  `_fireparq/` durably (default permissions; the mirror file stays `0600`).

- **Canonical `timestamp` is `Timestamp(Millisecond, UTC)` on every table (#491,
  PR #539).** It was `Timestamp(Second, UTC)`, which Parquet has no logical type
  for, so DuckDB, Spark, Trino and ClickHouse read it as `BIGINT`. It is now a
  Parquet `TIMESTAMP(MILLIS, isAdjustedToUTC=true)` and keeps the milliseconds of
  the Firehose block time (Antelope blocks show `.500`). Antelope
  `actions.block_time` uses the same type. `date`, time partition directories and
  the cursor's `last_timestamp` are still derived from the whole-second block
  time, so blocks land in the same partitions. Solana `timestamp` / `date` stay
  null when `block_time` is missing.
- **Day directories are `day=DD` (#493, PR #543).** Time partitioning wrote the
  day of the month as `date=DD`, which collided with the `date` column in
  Hive-aware readers (DuckDB read `date` as a day number; Polars failed). New
  output uses `year=YYYY/month=MM/day=DD/...`; `--partition date` keeps its name.
  `rollup` accepts legacy `date=` directories and keeps their key, and
  `truncate -p day=DD` (or `-p date=DD`) matches both.
- **Unique column names on every table (#492, PR #534).** Tron `transactions`
  had two `timestamp` columns; the transaction's own times are now
  `tx_timestamp_ms` and `expiration_ms` (raw `Int64` milliseconds, set by the
  sender and not validated on chain). A contract test checks every table of every
  chain for unique names and a Parquet round trip. NEAR `state_changes` now
  writes `block_id` / `parent_id` in base58 like the other NEAR tables (it used
  `0x` hex, so it could not be joined to `blocks`).
- **Per-chain schema changes.** Every chain gains, renames or retypes columns;
  see [Schema changes by chain](#schema-changes-by-chain): EVM (#494, #495,
  #496, #497), Solana (#500, #502, #503, #550), Beacon (#504, #505), NEAR (#506,
  #507, #550), Antelope (#508, #550), Tron (#492, #509, #550), Cosmos (#510) and
  Bitcoin (#511).

#### S3, credentials and configuration

- **S3 writes need an explicit URI; `.env` is read from the working directory
  only (#617, PR #623).** `fireparq` used to load `.env` from the current
  directory or any parent directory, and `build` / `partitions build` expanded a
  relative `--output` (including the default `.`) into `s3://$S3_BUCKET/<path>`,
  so a run started below a directory holding a production `.env` could write to
  the production bucket. Now `.env` is loaded from the working directory only,
  or exactly the file given with `--env-file` / `FIREPARQ_ENV_FILE`; parent
  directories are never searched; a malformed file is an error; and startup
  names the loaded file and the variables it supplied, never their values. With
  `--s3-bucket` / `S3_BUCKET` set, `build` and `partitions build` reject a
  relative output (and `partitions build` a missing one) before contacting the
  endpoint; the bucket option only checks the bucket of an explicit S3 output.
  `partitions build --output` is required and `partitions build` reads its
  existing index from the exact destination. `verify` runs that write roots or
  reports refuse a data path that only the shorthand resolved to S3. `build` logs its resolved output and mirror
  destinations, and `partitions build` its index destination, before the first
  write.
- **Destructive commands no longer fall back to `S3_BUCKET` (#481, PR #549).**
  `truncate`, `merge` and `rollup` fail with `path does not exist` for a relative
  path that does not exist locally, naming the `s3://` URI to pass. Read-only
  commands (`scan`, `inspect`, `validate`, `partitions ls/resolve/shard/validate`,
  and `verify` runs without the `roots` check or report outputs) keep the
  shorthand. `roots` is part of every `verify` profile, so a default `verify`
  needs the explicit URI.
- **S3 cursors use their exact bucket (#470, PR #573).** An explicit
  `s3://bucket/key` cursor selects its own bucket and key; relative cursor paths
  (including `--cursor-template` expansions) inherit the output bucket and
  prefix. An explicit S3 output must agree with `--s3-bucket` / `S3_BUCKET`, a
  bucket-bound endpoint rejects a different cursor bucket, and an S3 cursor needs
  complete explicit AWS credentials even with local output.
- **Native S3 ingestion uploads (#520, PR #613).** Authenticated protected
  `build` encodes each part to a private disk spool, streams one conditional
  PUT, and verifies the object through a second spool before committing.
  Native ingestion requires an HTTPS endpoint, caps each encoded part at
  5,000,000,000 bytes and rejects serialized footers above 32 MiB, even during
  resume verification; an oversized part fails with its journal retained instead
  of falling back to multipart. Upload and readback each have a 15-minute
  deadline with a 10-second connect timeout. Allow temporary disk for about two
  encoded parts.
- **Firehose credentials are scoped to the destination provider (#562, PRs #566,
  #615).** Credentials are chosen from the resolved host after endpoint
  overrides. The HTTPS hosts of built-in Pinax aliases use `PINAX_API_KEY` /
  `PINAX_API_TOKEN`,
  with `SUBSTREAMS_API_KEY` / `SUBSTREAMS_API_TOKEN` as legacy Pinax-only
  fallbacks; the hosts of built-in StreamingFast aliases use `STREAMINGFAST_API_KEY` /
  `STREAMINGFAST_API_TOKEN`. Automatic selection requires port 443; unknown hosts,
  other ports, URLs with user info and plaintext endpoints get no ambient
  credential. For custom
  endpoints, choose variables with `--api-key-envvar` / `--api-token-envvar`
  (`API_KEY_ENVVAR` / `API_TOKEN_ENVVAR`); an unset or blank selected variable
  omits its header, and startup warns whenever an explicitly selected credential
  is sent to a non-Pinax host. Logs show host and variable names, never values.
- **Built-in `--network` aliases (#535, PR #541).** The registry is regenerated
  from The Graph networks registry (v0.8.4). Thirteen aliases are removed
  (`bnb-op`, `bnb-svm`, `fantom`, `fuse`, `gnosis-chiado-cl`, `mode-mainnet`,
  `moonbeam`, `moonriver`, `ronin`, `scroll`, `scroll-sepolia`, `telos`,
  `telos-testnet`) and rejected during argument parsing by `build` and
  `partitions build`. `near-mainnet`,
  `near-testnet`, `tron` and `tron-evm` moved to StreamingFast endpoints and need
  a StreamingFast credential; `arc`, `megaeth`, `robinhood`, `tempo` and
  `xlayer-mainnet` are new.

#### Maintenance

- **`rollup` in-place runs need `--delete-source`, and only time partitions are
  rolled up (#478, PRs #536, #624).** Without `--output`, `rollup` fails unless
  `--delete-source` is passed (the copy used to be written next to its sources).
  Rollup reads only `part-*.parquet` files below a partition finer than
  `--partition` (`hour=`, `minute=`, `second=`); `block_range=` and unpartitioned
  files are left to `merge`. Outputs are named `part-<run>-NNNNNN.parquet` with
  `--delete-source` and `part-rollup-<run>-NNNNNN.parquet` in copy mode, where
  `<run>` is a random id per run; a copy-mode re-run replaces its earlier copies
  in each target partition it rewrites, and existing files are never
  overwritten. Do not rely on `part-000001.parquet` names.
- **`truncate` filters must all match, and deletes need `--yes` (#481, PR
  #549).** Filters on different keys are ANDed (`-p year=2026 -p month=01`
  selects January 2026, not all of 2026 plus every January); filters on the same
  key still match either value. Path filters such as `year=2026/month=01/day=15`
  work, and malformed filters are rejected. Without `--yes` (or `--dry-run`),
  `truncate` prints a summary (file count, size, the first 10 paths and root
  artifacts) and exits non-zero without deleting.
- **`merge` and `rollup` refuse mixed schemas and value metadata (#479, PRs
  #542, #624).** Both commands paired columns by position, so a partition that
  mixed two schemas could silently drop or swap columns before its sources were
  deleted. They now compare names, types, nullability and order, and the chain
  name, block type, encodings, vote and failed-transaction coverage, synthetic
  timestamps, stream mode and rollup copy marker. A mismatched partition is left
  untouched and reported, and the command exits non-zero after processing the
  others.
- **Protected datasets refuse destructive maintenance (#468).** `truncate`,
  in-place `rollup` and source-deleting `rollup` are refused on a dataset with
  ingestion authority; guarded `merge`, metadata artifacts and copy-only
  `rollup` to a separate output remain available. Legacy S3 merge journals from
  the old expiring lock are refused and need a reviewed migration.

#### Verify

- **`merkle_v2` roots (#487, #490; PRs #533, #540, #621).** Roots use a new
  versioned algorithm recorded as `merkle_version` in `merkle_roots.parquet` and
  in the report (`report_schema_version` `2.0.0`). Leaves and interior nodes are
  domain-separated, odd nodes are promoted, and the row count is committed, so a
  duplicated trailing row changes the root. Every Arrow type has an explicit
  encoding (specified in `docs/verifiability-hash-strategy.md`), physical
  variants of the same data encode identically, nested `Struct` values are
  encoded field by field, and unknown types are an error. Timestamps were hashed
  as a constant before, so changing one did not change the root. Every root
  changes; registries without `merkle_version` are read as `merkle_v1` and
  reported as mismatches until rebuilt with `--update-registry`.
- **One registry per network (#488, PR #546).** The registry is
  `<output>/<chain_name>/_fireparq/merkle_roots.parquet` (#647), shared by the
  network's tables, and published reports go to
  `<output>/<chain_name>/_fireparq/verify_runs/<run_id>/report.json`.
  The chain comes from file metadata and the table from the directory layout;
  `--chain` / `--table` are only needed for data without that information, and a
  contradicting value is an error. Reserved artifacts and the configured
  registry and report paths are never hashed as data. Partition keys come from
  the `k=v` directories above each file, whatever path was verified. `verify`
  warns while a registry exists at the old default location.
- **Registry integrity (#489, PRs #555, #621).** A failing run never writes the
  registry: nothing is written after a protocol failure, an early stop or a
  root mismatch (unless `--update-registry`), and partly read partitions are never
  recorded. `--update-registry` reports replaced roots as `updated` and exits 0
  once it has written. Registry rows are keyed by `network`. Local writes take
  `merkle_roots.parquet.lock` and replace the file atomically; S3 writes make one
  conditional put with no retry or unconditional fallback.

#### Partitions

- **`partitions.parquet` v2 with verified finalized coverage (#486, PRs #592,
  #618).** Index construction checks every finalized canonical block, preserves
  backward or repeated timestamp runs and records explicit coverage and span
  proofs. Current-head and clipped spans stay incomplete. Default resolution
  refuses incomplete or disjoint matches; `--all-spans --json` returns separate
  complete runs. v1 indexes written by `v0.7.x` have no coverage metadata:
  they can still be listed, but resolution, sharding and resume refuse them
  until they are rebuilt (`partitions build --overwrite`).
- **Index time columns are `Timestamp(Millisecond, UTC)` (PR #618).**
  `start_time`, `end_time` and `routing_start_timestamp` are written as Parquet
  `TIMESTAMP(MILLIS, UTC)`; values remain whole seconds. Older `fireparq`
  releases cannot read the new indexes, so upgrade readers first.
- **Existing indexes need `--resume` or `--overwrite` (#483, PR #545).** A
  bounded `partitions build` that finds an index fails unless `--resume` or
  `--overwrite` is passed, instead of replacing or duplicating rows. A resumed
  build starts at the stored frontier and rejects an explicit `--start-block`
  past it; re-running a covered bounded range is a no-op.

#### Metrics

- **Names, labels and readiness (#475, PR #587).** Counters emit one `_total`
  suffix (dashboards using `*_total_total` must migrate), `files_written_total`
  drops its unbounded `partition` label, and the cumulative-average rate gauges
  and always-zero Solana `backfill_*` gauges are removed. The final flush is
  counted as `flushes_total{trigger="stream_end"}` (was `"shutdown"`), and memory
  flushes as `trigger="memory"`. `/ready` returns 503
  before the first valid stream message, during reconnects, after the stream
  ends and after `--metrics-stale-after-secs` (default 120) without a message;
  `/health` stays live through reconnects and the final commit.

### Fixes

#### Ingestion and cursor

- **A failed S3 `build` releases bucket ownership when that is provably safe
  (#468, PR #640).** `build` kept the S3 bucket owner after any error, even when
  nothing had been written (for example a Blocks `Unauthenticated` error or a
  stream failure before the first flush), so every other writing command on the
  bucket failed with `bucket ownership is held` until someone ran `recovery
  release` with provider-quiescence evidence. A failed `build` now releases the
  owner when every request it sent had a definite outcome, including a failed
  transaction left pending (the next `build` rolls it back or completes it
  before streaming). An HTTP 401/403 refusal of a part, control-record or
  cursor-mirror PUT counts as definite. Ownership is still kept after an
  uncertain request, a second shutdown signal or a panic, and the error names
  each kept owner, why it was kept and the exact recovery commands. Other
  mutating commands keep their behavior and log the same guidance. See
  [the exit-path record](../audit/s3-owner-safe-release.md).
- **A failed table write no longer loses rows (#464, PRs #532, #600).** The
  uncommitted window is discarded, authority and cursor do not advance, the
  process exits non-zero, and recovery removes parts the failed transaction had
  published before the window is replayed. Previously the error path flushed the
  other tables and saved the cursor past the lost rows.
- **An unreadable cursor no longer restarts ingestion from scratch (#465, PR
  #538).** A cursor that exists but cannot be loaded fails the run instead of
  re-ingesting from `--start-block` or genesis and overwriting the good cursor.
  With #468, a missing mirror is repaired from authority and an unreadable or
  corrupt mirror fails closed. `partitions build` also fails on an unreadable
  sibling cursor it would use to infer `--start-block`.
- **Local cursor saves are atomic (#465, #468).** The mirror is written to a
  private temporary file, synced, renamed, and its directory ancestry synced; S3
  mirror updates use one conditional write and an exact readback.
- **Failed cursor saves stop `build` (#469, PR #571).** A local mirror save gets
  three attempts with 1 s and 2 s back-off; an S3 update gets one conditional
  attempt. Exhausted or ambiguous saves stop `build` with a non-zero exit. The
  mirror is published after the all-table commit, so a failed save never loses
  rows.
- **The final flush on completion is checkpointed (#572, PR #576).** A completed
  stream could write its last batch and skip the final cursor save.
- **Blocks below `--start-block` are no longer written (#466, PR #544).** When
  the start block is above the last irreversible block, Firehose serves from
  LIB+1; those blocks are now skipped, logged once and counted.
- **Live runs reconnect when the stream closes cleanly (#466).** A clean close
  used to exit 0, so `Restart=on-failure` supervisors never restarted it.
- **Fatal gRPC errors end the run (#472, PR #556).** `Unauthenticated`,
  `PermissionDenied`, `InvalidArgument`, `FailedPrecondition`, `OutOfRange`,
  `Unimplemented` and quota-exhausted `ResourceExhausted` (including statuses
  relayed as `Unknown`) stop with a hint instead of reconnecting forever; other
  `ResourceExhausted` errors are retried. Back-off and the stall timer reset only
  when a stream message arrives, and a run gives up after 30 consecutive failed
  attempts without a message.
- **Shutdown is prompt (#473, PR #579).** SIGINT/SIGTERM interrupt idle waits,
  reconnect back-off, connection attempts and startup checks; a block being
  processed still finishes. A second signal exits immediately with code 130.
- **CLI values that crashed or misbehaved are rejected or consistent (#471, PR
  #553; PR #615).** `--block-range-size 0` and `--stop-block 0` are rejected, and
  `build` rejects a `--stop-block` at or below the start (it is exclusive). A
  bounded run never sends `stop_block_num = 0`, so `--start-block 0
  --stop-block 1` ingests block 0 and stops. `0` disables `--flush-bytes`,
  `--flush-rows`, `--flush-interval-secs`, `--stream-idle-timeout-secs` and
  `--reconnect-stall-timeout-secs` instead of flushing after every block or
  causing reconnect storms. API keys and tokens are trimmed, and a credential
  that cannot be sent as a header is a startup error instead of a panic.
- **One partition per mapper flush (#477, PR #581).** An unreachable writer path
  that re-split partitions (interpreting millisecond timestamps as seconds) is
  removed; all tables are validated before any publication.
- **Legacy Antelope cursors with `bytes_encoding=auto` validate against
  `hex_no_prefix` (#550, PR #622).**
- **Help text and messages match protected resume (PRs #639, #641).** Root and
  `build` help say a rerun resumes from the `.fireparq-ingest/` authority, with
  `_fireparq/cursor.parquet` only an optional mirror (`--cursor none`), and no longer claim
  that `build` skips missing blocks after probe retries (only `partitions build`
  probes). The startup summary reads `missing_blocks     not probed; the stream
  delivers only produced blocks`. With a bucket option set, the error for the
  default output `.` suggests `--output "$(pwd)"` or `./output` instead of `./.`.

#### Maintenance

- **`rollup` re-runs no longer lose or duplicate rows (#478, PR #536).** An
  in-place re-run with `--delete-source` overwrote its earlier output and then
  deleted it as a source (on mainnet test data, the second run deleted the whole
  dataset); a re-run without it stacked duplicates. Re-runs now only roll up
  files still below the target granularity and never overwrite or delete their
  own output.
- **`rollup` and `merge` leave dataset artifacts alone (#478, #647).** The
  `_fireparq/` directory and the legacy root `cursor.parquet`,
  `partitions.parquet`, `merkle_roots.parquet` and `verify_runs/` are skipped.
- **An interrupted `merge` no longer leaves duplicate rows (#480, PR #561).**
  Each partition merge is journaled in `_fireparq_merge.json`, and the next
  `merge` (or `fireparq recovery recover <path>`) finishes or undoes an
  interrupted merge first: it deletes the remaining original parts if the merge
  had committed, and otherwise deletes the partial outputs and merges again.
  Local outputs are written through a synced temporary file.
- **An interrupted `rollup` no longer leaves duplicate rows (#478, #522; PR
  #624).** Rollup journals each target partition in `_fireparq_rollup.json`,
  writes local outputs through synced temporary files, syncs source deletions
  and finishes or undoes interrupted partitions before discovering sources. S3
  source reads retry transient failures of the same pinned object version.
  `merge` leaves partitions below an unfinished rollup alone.
- **Copy-mode `rollup` recognizes its earlier copies after `merge` (#478, PR
  #624).** Copies carry the footer marker `firehose-parquet.rollup_copy=true`,
  which `merge` keeps.
- **Merging parts at an S3 bucket root keeps every row (#480).** Outputs are
  numbered after every source instead of overwriting `part-000001.parquet`.
- **Overlapping `merge` runs are refused (#480, #468).** Local merges hold the
  directory guard plus `.fireparq-merge.lock`; S3 merges hold the bucket-wide
  owner. A partition that a merge on an enclosing or nested path is working on
  is skipped.

#### Verify, validate and partitions

- **`verify` runs beside `build` and handles concurrent rewrites (#489, PR
  #621).** `verify` reads without taking dataset ownership and never recovers or
  deletes anything. Partitions still being written are reported as `open` (from
  the protected authority or a legacy cursor) and are neither compared nor
  recorded; so is every partition of a non-final stream. A file added, removed
  or replaced during the scan fails the run before anything is compared or
  written. An unfinished merge or rollup journal is refused before any row is
  read.
- **`verify` memory no longer grows with row count (#521, PR #564)**; see
  Performance.
- **`validate` detects timestamp reversals (#484, PRs #537, #618).** The
  canonical timestamp was downcast to `Int64`, so every value read as 0. Any
  timestamp unit is now read, nulls are compared against the last known value,
  comparisons use milliseconds, and reports print `.mmm`.
- **`block_range` partition rows are ordered numerically (#482, PR #531).**
  Values were compared as strings, so `10000000` sorted before `8000000`,
  producing false overlaps, scrambled `ls` / `shard` output and empty
  `--from` / `--to` windows.
- **Partition probing is reliable (#485, PRs #583, #618).** Probe timeouts no
  longer look like missing blocks, and live `partitions build` keeps its last
  snapshot and retries transient failures with back-off (up to 300 s) instead of
  exiting.
- **`partitions build` validates its arguments at parse time (PR #639).**
  `--output` is required by the parser (a missing output, including
  `--s3-bucket` alone, fails before anything runs), `--network` accepts only
  built-in aliases and lists them on error, and `--stop-block 0` is rejected
  before any endpoint is contacted.
- **`recovery` reads `AWS_ENDPOINT_URL_S3` (PR #639).** Its `--aws-endpoint-url`
  read only `AWS_ENDPOINT_URL`, so an environment set up for `build` or `merge`
  sent `recovery` to AWS instead of the configured S3-compatible endpoint.
  `AWS_ENDPOINT_URL` is still read when neither the flag nor
  `AWS_ENDPOINT_URL_S3` is set; `AWS_ENDPOINT_URL_S3` wins when both are.
- **`partitions validate` checks v2 indexes (#486, PR #618).** It used to report
  any loadable v2 index as valid; `--allow-gaps` now has no effect on v2 indexes
  and warns.

#### Documentation

- **EVM log indices and absent tables are documented (#498, PR #575).**
- **Examples match the CLI (PR #615).** README examples include the `build`
  subcommand, and `.env.example` is generated from the CLI definitions and
  drift-tested.

### Performance

- **Bounded concurrent table work inside each flush (#516 stage A, PR #629).**
  `build` encodes and publishes one flush's parts concurrently:
  `--flush-encode-concurrency` (default 2), `--flush-publish-concurrency`
  (default 4; for local output also the threads that stage, publish and verify
  files) and `--flush-inflight-bytes` (default 256 MiB of encoded parts, in
  memory or in the native-S3 disk spool; one larger part runs alone with a
  warning). Receipts that are ready together are journaled in one write and each
  is durable before its part publishes; authority and the mirror advance only
  after every part is published and verified; the first error drains started
  work and keeps the journal. Output bytes and names are identical to serial
  work, and `--flush-inflight-bytes 1` makes it strictly serial. The gRPC stream
  still pauses during each flush (stage B, #630).
- **Canonical identity columns are encoded once per block (#512, PR #548)**,
  byte-identically.
- **Hex and base58 columns no longer allocate a string per value (#514, PR
  #563)**, byte-identically.
- **Fixed-size base58 conversion uses safe integer limbs (#565, PR #598).**
  32-byte keys and 64-byte signatures use a stack encoder; other lengths,
  including Tron checksummed addresses, keep `bs58`. Output is unchanged.
- **EVM decimal conversion writes directly into Arrow (#513, PR #596).** Up to
  32 significant bytes use a stack buffer; larger inputs keep an
  arbitrary-length fallback. Values are unchanged.
- **Protobuf byte fields share the owned Firehose payload (#518, PR #606).**
- **Tuned gRPC receive transport (#517, PR #602)**; see New features.
- **Adaptive compressed file targets (#515, PR #605)**; see Breaking changes.
- **Bounded Parquet lookup properties (#519, PR #608)**; see Breaking changes.
- **Native S3 uploads stream from a disk spool (#520, PR #613)**; see Breaking
  changes.
- **`verify` streams partition roots (#521, PR #564).** Roots are built as rows
  stream in, with O(log n) memory per partition; roots are identical.
  `--checks protocol` reads only the columns its checks use and hashes nothing.
  S3 objects are prefetched, up to 4 at a time within a 256 MiB budget.
- **`rollup` streams bounded batches (#522, PR #604).** Each target group is
  validated, then one input batch and one output part are processed at a time,
  with a separate 32 MiB estimated row-group memory budget. S3 sources are read
  through pinned byte ranges. Output file counts can change.
- **Bounded S3 maintenance concurrency (#523, PR #609).** Cleanup runs at most
  ten individual DELETE requests at once; a failure stops new dispatch and
  drains started requests while keeping ownership on an uncertain result.
  `merge` reads ordered windows of at most four objects and 64 MiB of listed
  compressed bytes (an oversized object runs alone), and every read verifies its
  original ETag/version.
- **Projected dataset validation (#524, PR #599).** `validate` decodes only the
  canonical id/height/time columns and compares cached partition endpoints,
  which also fixes endpoint selection when partitions overlap.

Measured results are summarized under [Highlights](#performance).

### Internal

- **Structure (#525–#530).** Ingestion setup, runtime state and flush windows
  live in `blocks/src/bin/ingestion/` (#525, PR #611); chain-family decisions come
  from one `ChainKind` / `ChainProfile` table in `blocks/src/chain.rs` (#526, PR
  #614); CLI argument structures share `AwsArgs` and S3 clients are built by
  named policy (#527, PR #610); `cli.rs` is split into modules (#528, PR #612);
  `merge`, `rollup`, `truncate`, `verify`, `scan` and `validate` share one local/S3
  engine per maintenance step, with byte-identical output in 24 scenarios (#529,
  PR #620); Firehose RPC clients share credential insertion and transport
  construction (#530, PR #603).
- **Tests.** A cross-chain schema contract test maps every table of every chain
  under every encoding (#492); an offline EVM golden regression over retained
  mainnet blocks covers both mapping paths and EIP-7702 (#499, PRs #588, #616);
  real-binary ingestion regressions run against a mock Firehose (PR #619); a
  weekly `Network endpoints` workflow checks every built-in endpoint (#535); a
  flaky partition-boundary test gets its own directory (#551, PR #552).
- **Test-only fault hooks (#639).** `FIREPARQ_TEST_MERGE_CRASH_AT`,
  `FIREPARQ_TEST_ROLLUP_CRASH_AT` and `FIREPARQ_DEBUG_FAULT`, which abort or fail
  the binary at a named step for recovery tests, are read only by debug builds
  (`cfg!(debug_assertions)`, as built by `cargo test`). Release binaries used
  to honor the two maintenance hooks, so an inherited variable could abort
  production maintenance. Harnesses that need them in an optimized binary can
  build with `CARGO_PROFILE_RELEASE_DEBUG_ASSERTIONS=true`.
- **Advisory workflow (#639).** The cargo-deny job moved to
  `.github/workflows/advisories.yml`, which `ci.yml` calls and which also runs
  weekly and on manual dispatch. Two deny-level clippy lints in test code were
  fixed.
- **Schema reference.** `docs/schemas/<chain>.md` is generated from the code
  (`cargo run -p blocks --example dump_schemas`) and drift-tested.
- **Dependencies and CI.** See Security under Highlights. The release and Docker
  workflows gained dry-run modes (PRs #627, #628).

## Known limitations and follow-ups

- **NEAR `state_changes` is empty (#625).** Every known StreamingFast NEAR
  producer leaves the block's state changes empty, so the rebuilt table (#507)
  has no rows on their output. The mapper is ready for a producer that emits
  them.
- **NEAR, Tron and Cosmos are qualified against RPC and public sources only.**
  Their mapper output was compared value by value with archival RPC, public
  datasets or retained raw blocks, not with a Firehose stream of those chains
  (no usable Firehose quota was available during the audit). EVM, Solana,
  Beacon, Antelope and Bitcoin were compared with Firehose data. Qualification
  against real Firehose data is tracked in #631.
- **#516 stage B (#630).** Stage A overlaps the table work inside one flush,
  but the gRPC stream is still not read while a flush commits. Decoupling
  receive and mapping from the writer needs a reviewed session/frontier
  extension; the requirements are in the
  [design record](../audit/516-concurrency-design.md#stage-b-follow-up).
- **object_store 0.14.** Clearing RUSTSEC-2026-0194 and RUSTSEC-2026-0195
  (quick-xml 0.38, reachable only through S3 XML responses from the configured
  endpoint) needs the breaking object_store 0.14 upgrade (#632). Both
  advisories are ignored in `deny.toml` with that reason.
- **Unmaintained dependencies.** `backoff` (gRPC reconnect back-off,
  RUSTSEC-2025-0012) and `bincode` 1.3 (RUSTSEC-2025-0141) are unmaintained and
  ignored in `deny.toml` until they are replaced (#633).
- **No real-data `gas_changes` fixture.** The offline EVM golden regression
  covers two retained mainnet blocks, but neither records a gas change, so
  `gas_changes` is only covered by synthetic tests (#634).
- **S3 ownership is bucket-wide (#636).** Only one mutating command can run per
  bucket, so maintenance cannot run next to a live `build` on the same bucket.
  An owner kept after an ambiguous `build` request, or after any error of a
  maintenance command, needs `recovery release`, which requires the operator's
  confirmation that the provider finished every request of the previous writer;
  providers that cannot give that assurance cannot safely release a stuck owner
  through this command.
- **Protected datasets are bound to their location (#635).** Output authority
  binds the exact output location. A protected dataset copied or moved to
  another path or bucket (for example with `cp -R` or `aws s3 sync`) can still
  be read and verified, but `merge` refuses it (`authoritative output binding
  differs from the selected storage destination`) and it cannot be resumed
  there. There is no relocation procedure yet; build in the final location.
- **A malformed `./.env` breaks `--help` and `--version` (#637).** The env file
  is loaded before argument parsing, so fix or move a malformed file first.
- **No atomic multi-table snapshots for plain-glob readers.** Transactions make
  each flush all-or-nothing for `fireparq`, but a reader globbing table
  directories while `build` publishes can still see some tables of a flush
  before others.
