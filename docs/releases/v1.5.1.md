# firehose-parquet v1.5.1

`v1.5.1` is a patch release of [v1.5.0](v1.5.0.md). The Delta maintenance job
gains `OPTIMIZE=0`, for checkpoint-only runs beside a compaction run that
takes hours (#728). It changes no output format, schema or dataset state, and
the writer is unchanged: a v1.5.0 dataset resumes as it is, and no rebuild is
needed.

## Upgrade

- **Writers and maintenance jobs:** move to the new image tag
  (`ghcr.io/pinax-network/firehose-parquet:1.5.1`). Existing schedules behave
  as before: `OPTIMIZE` defaults to `1`. Files written after the upgrade carry
  `firehose-parquet.version` `1.5.1`; maintenance leaves the key out of a
  compacted day that spans the upgrade.
- **Beside a parallel backfill:** a run with `OPTIMIZE=0` and `VACUUM=0`
  next to the compaction run keeps the log tails short
  ([Checkpoint-only runs](../delta-maintenance.md#checkpoint-only-runs)). Only
  that run needs the new image: lanes on v1.5.0 keep running.
- **Rollback:** v1.5.0 runs on the same datasets. It reads `OPTIMIZE=0` as
  nothing and compacts, so remove the checkpoint-only schedule first.

## Known issues

- **Corrected on 2026-11-17: a checkpoint-only run does not make a backfill
  faster.** These notes said a writer's commit time grows with a table's
  commits since its last checkpoint. Measured after the release, the log tail
  explains only part of it: beside a 15-lane backfill one run cut the mean
  commit time from 25.9 s to 20.6 s and left the block rate unchanged, and
  beside a 10-lane backfill commit times did not change. See
  [Checkpoint-only runs](../delta-maintenance.md#checkpoint-only-runs).
- **Time one run before choosing the interval.** A checkpoint loads the
  table's whole state, and the log cleanup lists its whole `_delta_log/`. A
  run over 20 tables near version 33,000 took 147 s.

## New features

- **Checkpoint-only maintenance: `OPTIMIZE=0` (#728, #732).** A run only
  checkpoints a table after compacting it, and beside a parallel backfill a
  run takes hours, so tables went thousands of commits without a checkpoint,
  all of which a reader or a starting lane reads. `OPTIMIZE=0` skips
  compaction and the read of `blocks` for the open date; with `VACUUM=0` a
  run only writes a checkpoint and cleans up the log. It commits nothing, so it conflicts with
  neither the writers nor the compaction run. The `start` line gains
  `optimize`. See
  [Checkpoint-only runs](../delta-maintenance.md#checkpoint-only-runs).
