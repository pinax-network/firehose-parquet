# firehose-parquet v1.3.0

`v1.3.0` is a minor release of [v1.2.0](v1.2.0.md). It adds `fireparq
hypercore-reference`, a subcommand that snapshots HyperLiquid's `/info` into
small Delta reference tables beside a HyperCore lake, and moves rustls to
0.23.46 for four security advisories. Writers and the maintenance job are
otherwise unchanged: every block family keeps its schemas and digests, so a
v1.2.x dataset resumes as it is and no rebuild is needed.

## Upgrade

- **Existing writers and maintenance jobs:** move to the new image tag
  (`ghcr.io/pinax-network/firehose-parquet:1.3.0`) to pick up the rustls fix.
  Nothing else changes for any block family.
- **Maintenance schedules:** make sure no two maintenance runs of one lake can
  overlap, including a daily or weekly VACUUM job beside the frequent one; see
  the first known issue.
- **HyperLiquid reference tables** need their own bucket or root and their own
  S3 user; see [HyperLiquid reference tables](../hypercore-reference.md) and
  [`deploy/examples/hypercore-reference-cronjob.yaml`](../../deploy/examples/hypercore-reference-cronjob.yaml).

## Known issues

- **Overlapping maintenance runs duplicate rows**
  ([#717](https://github.com/pinax-network/firehose-parquet/issues/717)): two
  `fireparq maintenance` runs that compact the same date at once both commit,
  and the date's rows are duplicated. deltalake-core 1.0.0 does not treat two
  compactions removing the same files as a conflict. `concurrencyPolicy:
  Forbid` covers only one CronJob, so schedule a lake's maintenance CronJobs
  apart, or suspend the frequent job while a VACUUM job runs.
  `fireparq hypercore-reference` is not affected: its commits never retry.
- **Non-final output with a reorg deeper than one block never compacts**
  ([#715](https://github.com/pinax-network/firehose-parquet/issues/715)): only
  `--final-blocks-only=false` lakes are affected; the day keeps its parts and
  every maintenance run reports it.
- **SEC operations** ([#711](https://github.com/pinax-network/firehose-parquet/issues/711)):
  unchanged from v1.2.0. A live SEC writer can exit with `reconnect stalled`
  after two disconnects in one quiet day, and the 512 MiB SEC message default
  admits windows larger than the documented 3 GiB of writer memory can map.
- **HyperCore endpoint:** blocks 846903300–846903312, before the data origin,
  are still missing upstream
  ([firehose-hypercore#31](https://github.com/pinax-network/firehose-hypercore/issues/31)).

## New features

- **HyperLiquid reference tables: `fireparq hypercore-reference`** (#716).
  A new subcommand of the same binary and image snapshots HyperLiquid's
  `/info` into ten small append-only Delta tables (`hl_*`): spot tokens and
  pairs, perp dexes and assets, HIP-4 outcomes and questions, and the hourly
  funding premium. Readers join them with a HyperCore lake at query time
  through the SQL views of [HyperLiquid reference
  tables](../hypercore-reference.md). Three jobs (`outcomes`, `meta`,
  `funding`) run on a schedule
  ([`deploy/examples/hypercore-reference-cronjob.yaml`](../../deploy/examples/hypercore-reference-cronjob.yaml));
  every commit is a single conditional attempt, never over a concurrent one,
  and each job compacts and vacuums its own tables and backfills across runs.
  It is the Rust port of the Python job of
  [k8s-parquet#82](https://github.com/pinax-network/k8s-parquet/pull/82), with the same
  tables, payload hashes and views. **It needs its own bucket or root**, for example
  `s3://hypercore-ref`, never a fireparq dataset root (whose `build` would then
  refuse to resume), with an S3 user limited to its table prefixes
  ([The S3 user](../hypercore-reference.md#the-s3-user)). Set
  `AWS_ENDPOINT_URL_S3` and both keys for an `s3://` root; a URL in
  `HL_INFO_URL` that embeds a key is never printed.

## Fixes

- **rustls 0.23.46** (#718) clears RUSTSEC-2026-0346 (`Debug` impls of client
  session values expose TLS secrets), RUSTSEC-2026-0347 (buffered application
  data sent to the outer server after an ECH rejection), RUSTSEC-2026-0348
  (Brotli certificate decompression can allocate up to 1 GiB before
  authentication) and RUSTSEC-2026-0349 (an unauthenticated ServerHello can
  downgrade later connections to classical key exchange). Only `Cargo.lock`
  changed.
- **Maintenance docs no longer call an overlap safe**: the example CronJob and
  [Delta maintenance](../delta-maintenance.md) now say not to let two
  maintenance runs of one lake overlap (#717).

## Internal

- **Shared pieces for the reference crate** (#716): the maintenance crate
  exports `is_conflict`, `sorted` and `compact::StoreReader`;
  `firehose_parquet::delta::store::s3_data_client` builds a data-file client
  with three bounded retries beside `s3_log_client`, whose commits keep one
  attempt. The HyperCore decimal parser was restructured for reuse; the
  HyperCore writer's output and schema digests are unchanged.
- **Docs checked against v1.2.0** (#714): every page was re-verified against
  the code, the CLI reference gained the `maintenance` subcommand and flush
  sections, and the SEC schema reference links into the SEC notes instead of
  an unpublished spec.
