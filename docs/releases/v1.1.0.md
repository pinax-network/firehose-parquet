# firehose-parquet v1.1.0

> **Use [v1.1.1](v1.1.1.md) instead.** v1.1.0 can't read the control records
> that the v1.0.2–v1.0.7 Docker images wrote: `build` stops at startup with
> `control record checksum mismatch`
> ([#698](https://github.com/pinax-network/firehose-parquet/issues/698)).

`v1.1.0` is a minor release of [v1.0.7](v1.0.7.md). The Delta maintenance job
is now `fireparq maintenance`: one binary, one image and one version with the
writer. It changes no output format, schema or dataset state: a v1.0.7
dataset resumes as it is, and no rebuild is needed.

## Upgrade

- **Maintenance.** Point the maintenance CronJobs at the writer's image,
  `ghcr.io/pinax-network/firehose-parquet`, with `args: ["maintenance"]`. The
  image `ghcr.io/pinax-network/firehose-parquet-maintenance` is no longer
  published; its last release is v1.0.7. The settings, output and exit statuses
  are the same. See
  [`deploy/examples/delta-maintenance-cronjob.yaml`](../../deploy/examples/delta-maintenance-cronjob.yaml).
- **Writer.** `ghcr.io/pinax-network/firehose-parquet` needs the new tag. Its
  ingestion is unchanged since v1.0.4, and it now carries the maintenance job.
- **Release tarballs** ship `fireparq` only.

## Breaking changes

- **The maintenance job is `fireparq maintenance`** (#696).
  - **What's gone:** the separate `fireparq-maintenance` binary, its image and
    `deploy/maintenance/Dockerfile` are removed.
  - **What stays:** the maintenance crate is a library that `fireparq`
    links. `fireparq maintenance` reads the same environment variables, now
    also from an `--env-file`, prints the same JSON lines and exits 0, 1 or
    2. `fireparq maintenance --help` lists the settings.
  - **Metadata:** compacted files no longer carry
    `fireparq-maintenance.version`, since the job's version is the writer's.
    The row-order key is `fireparq.row_order` (it was
    `fireparq-maintenance.row_order`) in the footer and the OPTIMIZE commit.
    Files already compacted keep their keys.
  - **No DataFusion:** nothing links it any more. The compaction has been the
    crate's own since v1.0.6, so delta-rs's `datafusion` feature is off.
  - See [Delta maintenance](../delta-maintenance.md).
