# firehose-parquet v0.7.1

`v0.7.1` is a focused operator ergonomics release.

This patch release keeps the core data model stable while simplifying the default `fireparq` workflow, removing several operator-hostile switches, tightening startup failures, and making S3-backed maintenance commands easier to trust.

The biggest changes are:

1. a much smaller and more intuitive `build` CLI,
2. clearer default behavior for live mode, missing blocks, and missing genesis timestamps,
3. safer startup checks for built-in Firehose networks, and
4. more resilient and more observable S3-backed `merge` operations.

## Why this release matters

`v0.7.0` introduced the first large round of CLI cleanup. `v0.7.1` completes that operator-facing simplification pass.

If you mostly run `fireparq build`, the practical effect is that the default command path is now closer to what operators already expect:

- no manual byte-encoding selection,
- no `--live` toggle to remember,
- no `--skip-missing-blocks` toggle to remember,
- no bootstrap flag for first-streamable blocks with missing timestamps,
- and clearer debug output when you do need to troubleshoot behavior.

If you rely on maintenance workflows, this release also improves `merge` by adding row-based flushing, aligning flush controls with `build`, retrying S3 writes/deletes more aggressively, and exposing richer object-level logs behind a shared `--verbose` flag.

## Highlights

### 1. `build` is simpler by default

The main ingestion command now removes or inverts several flags that made the operator path harder to remember.

What changed:

- removed `--bytes-encoding` from `build`; encoding is now derived from block type/profile,
- removed the legacy `--chain` override from `partitions build`,
- replaced default-on booleans with operator-friendly disable flags:
  - `--without-extended`
  - `--without-votes`
- removed `--live` from `build`; omitting `--stop-block` now means live mode,
- removed `--skip-missing-blocks`; missing-block skipping now defaults on across build flows,
- made missing-genesis timestamp bootstrap automatic by default.

Examples:

```bash
# Live ingestion is now inferred when --stop-block is omitted
fireparq build --network mainnet

# Disable EVM extended tables only when needed
fireparq build --network mainnet --start-block 20000000 --stop-block 20001000 --without-extended

# Disable Solana vote transaction output only when needed
fireparq build --network solana-mainnet-beta --without-votes
```

This reduces the number of “special flags you have to know” for a normal deployment.

### 2. Encoding is now documented as a block-type contract

Because encoding is no longer operator-configurable, the README now documents the effective output contract directly.

The release includes a block-type encoding table that explains, per chain/profile:

- block identifier encoding,
- binary field encoding,
- notable chain-specific exceptions.

That makes the encoding story easier to reason about operationally and removes a whole class of CLI and validation complexity.

### 3. Built-in network startup fails earlier and more clearly

The built-in network registry was refreshed, and startup now fails earlier when a built-in endpoint is unavailable.

This matters for cases where a built-in alias resolves successfully but the provider endpoint is no longer usable. Instead of surfacing a misleading downstream error later in startup, `fireparq` now treats endpoint availability as a first-class startup concern.

For operators, the practical win is simple: bad built-in endpoint state is reported closer to the real root cause.

### 4. `merge` is more practical for S3-backed datasets

`merge` received several operator-focused improvements in this release:

- explicit retries for S3 uploads and deletes,
- object-level verbose logging for uploaded/deleted files,
- a shared `--verbose` mechanism instead of a merge-only logging switch,
- `--flush-rows` support for merge,
- `--flush-bytes` defaults aligned with `build`.

This makes long-running S3-backed maintenance jobs easier to debug and less likely to fail permanently on transient object-store errors.

## Recommended usage patterns

### Default live ingestion

```bash
fireparq build --network mainnet
```

Use this when you want the default live-follow behavior. `--stop-block` now defines bounded mode; omitting it keeps the stream open.

### Bounded historical ingestion

```bash
fireparq build --network mainnet --start-block 20000000 --stop-block 20001000
```

Use this when you want a fixed historical range.

### Debug a command with richer logs

```bash
fireparq build --network mainnet --verbose
```

Use `--verbose` when you need deeper startup, cursor, retry, or per-object operational detail without making default logs noisy.

### Run `merge` with row and byte-based flush controls

```bash
fireparq merge s3://my-bucket/solana-mainnet-beta --flush-bytes 33554432 --flush-rows 100000 --verbose
```

Use this when you want smaller merged parts together with full object-level logging for uploads and deletes.

## Upgrade guidance

If you are upgrading from `v0.7.0`:

- remove any use of `--bytes-encoding` from `build` scripts,
- remove any use of `partitions build --chain`,
- replace `--extended false` with `--without-extended`,
- replace `--with-votes false` with `--without-votes`,
- stop passing `--live`; omit `--stop-block` instead,
- stop passing `--skip-missing-blocks`; the permissive missing-block behavior is now default,
- stop passing `--bootstrap-missing-genesis-timestamp`; bootstrap is now automatic,
- use the README encoding table as the source of truth for per-chain output encoding,
- prefer `--verbose` when you want deeper debug logs from build/merge/rollup workflows.
