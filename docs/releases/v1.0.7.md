# firehose-parquet v1.0.7

`v1.0.7` is a patch release of [v1.0.6](v1.0.6.md). It fixes a loop in
`fireparq-maintenance`'s repair of days into the writer's row order, found in
the v1.0.6 rollout. It changes no output format, schema, CLI flag or dataset
state: a v1.0.6 dataset resumes as it is, and no rebuild is needed.

## Upgrade

- **Maintenance image.** `ghcr.io/pinax-network/firehose-parquet-maintenance`
  needs the new tag.
  - Give the maintenance Job's runs time for a day's repair, which commits a
    table's day all or nothing. The example CronJob now allows 3 h; on
    riv-dev1 the first v1.0.6 run took 90 min on BSC (`calls` alone 44 min).
  - Files v1.0.6 split at the target size stay as they are: two files where
    one would do.
- **Writer image.** `ghcr.io/pinax-network/firehose-parquet` changes only its
  version.

## Fixes

- **A repaired day is no longer repaired again on every run**
  ([#690](https://github.com/pinax-network/firehose-parquet/issues/690),
  [#694](https://github.com/pinax-network/firehose-parquet/pull/694)).
  - **The loop:** v1.0.6 rolled a repaired bin to a second file at the target
    size, inside a block. The planner took the two files, which share that
    block, for an overlap and sorted them again every run. The rows were
    rewritten unchanged, but the table spent its one repair per run on that
    day and never reached its older days. On riv-dev1 this hit Base and BSC
    `storage_changes`, whose delta-rs files were just over 256 MiB.
  - **The fix:** each bin is now written as one file, as delta-rs writes a
    bin, so no block is split across files. Two files in writer order that
    only share a boundary block are no longer an overlap: concatenated in
    block order, the split block's rows stay in order.
- **The example maintenance CronJob gives its runs 3 h**
  ([#694](https://github.com/pinax-network/firehose-parquet/pull/694)),
  both the 15-minute job and the weekly full VACUUM, which also compacts
  first. A shorter deadline kills every repair run in the same table, and
  that table and the ones after it are never compacted.
