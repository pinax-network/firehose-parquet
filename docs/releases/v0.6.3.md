# firehose-parquet v0.6.3

`v0.6.3` is a focused operator release for the main `fireparq build` workflow.

The headline improvements are:

1. stricter and more practical handling for genesis / first-streamable blocks with missing timestamps,
2. clearer restart behavior for `--cursor-override`, and
3. easier S3 inspection workflows through shorthand paths in `scan` and `inspect`.

This release also hardens S3 credential validation so misconfigured output destinations fail earlier and more clearly.

## Why this release matters

`v0.6.2` introduced the newer `build` subcommand shape and a broader cleanup of the main CLI surface. `v0.6.3` focuses on the first set of real operator edge cases that surfaced after that work landed.

This release helps most when you are:

- bootstrapping Ethereum or similar chains from the first streamable block,
- running strict timestamp ingestion without wanting to fall back to nullable timestamps globally,
- restarting jobs intentionally with `--cursor-override`,
- scanning or inspecting Parquet data in S3 without remembering the full bucket URI,
- debugging S3 output misconfiguration and wanting an earlier failure signal.

The short version: `v0.6.3` makes the main ingestion CLI easier to trust when the inputs or runtime state are slightly messy.

## Highlights for new users

### 1. Strict timestamp mode can now bootstrap past genesis / first-streamable edge cases

The biggest ingestion improvement in `v0.6.3` is the opt-in bootstrap path for chains whose first streamable block does not carry timestamp metadata.

That matters most for Ethereum-style genesis behavior, where strict mode used to fail immediately at the start of a run.

Examples:

```bash
# Strict mode with bootstrap for the first timestamp-less genesis block
fireparq build \
  --network mainnet \
  --partition date \
  --bootstrap-missing-genesis-timestamp \
  --live

# Strict bounded run with bootstrap enabled
fireparq build \
  --network mainnet \
  --start-block 0 \
  --stop-block 100000 \
  --partition date \
  --bootstrap-missing-genesis-timestamp
```

What this improves in practice:

- strict mode no longer forces a fallback to nullable timestamps just because the first block lacks timestamp metadata,
- logs are more explicit about genesis / first-streamable timestamp failures,
- bootstrap behavior preserves the initial block data instead of silently dropping it once a later timestamp anchor is found.

### 2. `--cursor-override` now means restart from the requested CLI bounds

`v0.6.3` also fixes the surprising behavior where `--cursor-override` still resumed from the stored cursor position instead of respecting the newly requested range.

Examples:

```bash
# Restart from the requested start block even if a cursor already exists
fireparq build \
  --network mainnet \
  --start-block 1 \
  --partition date \
  --cursor-override \
  --live

# Restart live mode from the endpoint default when no start block is provided
fireparq build \
  --network mainnet \
  --partition date \
  --cursor-override \
  --live
```

For operators, the important behavior is simple: `--cursor-override` now behaves like a real restart override rather than merely suppressing cursor parameter mismatch validation.

### 3. `scan` and `inspect` support shorthand S3 paths

This release improves day-to-day inspection ergonomics by letting `scan` and `inspect` resolve shorthand keys through `S3_BUCKET` when no local file matches.

Examples:

```bash
# Local file still wins when it exists
fireparq scan ./output/mainnet/partitions.parquet

# Fall back to S3_BUCKET for shorthand keys
S3_BUCKET=my-bucket fireparq scan mainnet/partitions.parquet

# Same shorthand behavior for inspect
S3_BUCKET=my-bucket fireparq inspect mainnet/blocks/year=2015/month=07/date=30/part-000001.parquet
```

Lookup order is now:

1. explicit `s3://bucket/...` URIs are used as-is,
2. non-URI paths use the local filesystem when the path exists,
3. otherwise, if `S3_BUCKET` is set, relative paths fall back to `s3://<bucket>/<path>`.

### 4. S3 output misconfiguration fails earlier

`v0.6.3` also hardens S3 output startup so unresolved explicit AWS credentials fail fast instead of surfacing later in a less obvious way.

This is not a new CLI feature, but it is an operator-quality improvement for anyone writing directly to S3-compatible storage.

## Recommended usage patterns

### Bootstrap a strict Ethereum ingestion run from genesis

```bash
fireparq build \
  --network mainnet \
  --partition date \
  --bootstrap-missing-genesis-timestamp \
  --live
```

Use this when you want strict timestamps overall, but you do not want the run to fail just because the first streamable block lacks timestamp metadata.

### Restart from CLI bounds instead of resuming from a stored cursor

```bash
fireparq build \
  --network mainnet \
  --start-block 1 \
  --partition date \
  --cursor-override \
  --live
```

Use this when you want an intentional restart and do not want the old cursor position to silently win.

### Inspect remote data without typing the full bucket URI

```bash
S3_BUCKET=my-bucket fireparq inspect mainnet/partitions.parquet
```

Use this when you know the object key or relative layout but do not want to retype `s3://<bucket>/...` every time.

## Upgrade guidance

If you are upgrading from `v0.6.2`:

- use `--bootstrap-missing-genesis-timestamp` when strict mode should remain enabled but genesis lacks timestamp metadata,
- expect bootstrap mode to preserve genesis/bootstrap blocks instead of silently skipping them,
- expect `--cursor-override` to restart from the requested CLI bounds rather than resuming from the stored cursor position,
- use shorthand keys with `scan` and `inspect` when `S3_BUCKET` is configured,
- expect S3 credential mistakes to surface earlier during startup.
